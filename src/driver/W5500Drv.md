# W5500Drv — W5500 driver for RP2040

`W5500Drv.{h,cpp}` in this folder are a copy of the arduino-pico 5.6.0 driver
(`libraries/lwIP_w5500/src/utility/w5500.*`, BSD-3, copyright kept); the OpenKNX changes are under the same
license. `src/OpenKNX/Network/Module.cpp` uses the class as `LwipIntfDev<W5500Drv>` when `OPENKNX_ETH_W5500` is set
on RP2040. ESP32 builds are not affected.

## Why a copy

`sendFrame()` is public and not virtual; the register helpers it is built from (`wizchip_*`,
`getSn_*`/`setSn_*`) are private to the core class. KNXnet/IP routing needs one change in `sendFrame()`
(03_08_05 2.3.5: a KNX IP device or router stops sending ROUTING_INDICATIONs as soon as it receives a
ROUTING_BUSY).

## Changes against the core driver

| Change | Effect |
|---|---|
| for a ROUTING_INDICATION `sendFrame()` writes the frame to the chip, then looks for a ROUTING_BUSY among the first 16 frames in the receive buffer before `SEND` (any destination) | a ROUTING_INDICATION is not sent past a ROUTING_BUSY already in the chip; a router's KNX stack keeps it queued (a ROUTING_BUSY the stack does not receive, e.g. for another multicast group, counts as a refusal: dropped after `KNX_ROUTING_SEND_RETRIES`); on a `0x07B0` interface the frame is counted in PID 72 and confirmed negative |
| SPI as block transfers (`transfer(tx, rx, n)`) instead of one call per octet | frame and register access no longer bound by per-octet call cost |
| `SENDOK` of a frame awaited before the next send, not after its own; with an interrupt pin it is awaited right after `SEND`, as in the core driver, and the send then returns the frame length | without an interrupt pin the main loop runs on while the chip transmits; a send `TIMEOUT` is no longer reported to lwIP; with an interrupt pin `INTn` does not stay low on a pending `SENDOK` |
| the `SENDOK` wait ends 500 ms after `SEND`, after one last read of `Sn_IR`; the socket is then closed and opened again, and the frame being sent goes out on the reopened socket | a `SENDOK` that never comes does not hang the main loop; the frame without `SENDOK` is dropped (with an interrupt pin that is the frame just sent, and its send still returns the frame length); `net` shows the count as `W5500 socket reopens` |
| `_sendPending` cleared in `begin()`/`end()`; a socket that is not MACRAW, also after a failed reopen, ends the wait and fails the send; with no SEND pending one socket-state read checks it | chip reset and recovery do not block on a flag that never comes; a closed socket found before `SEND` fails the send |
| socket state otherwise read in the free-space wait only while space is short; space still short 1 ms after the wait began (the previous frame is already done there) fails the send and reopens the socket | one register read less per frame; a transmit buffer that does not drain does not hang the main loop, and the next send finds an empty buffer (counted with the reopens) |
| `end()` waits for `SOCK_CLOSED` at most 500 ms, then goes on as closed | a chip that never reports `SOCK_CLOSED` does not hang the main loop; `begin()` resets the chip anyway; `net` shows the count as `close timeouts` |
| `setSn_CR()` waits at most 1 ms for the chip to accept a command and reports failure: `begin()` fails, `end()` goes on, a RECV after the frame data drops that frame (the RECV after the length still returns it, since `RX_RD` has moved), a SEND fails the send | a chip that never clears `Sn_CR` (e.g. reads 0xFF) does not hang the main loop; `net` shows the count as `command timeouts` |
| `readFrameSize()` checks the 2-octet frame length before it moves `RX_RD`: below 2 or above 1524 octets (two 802.1Q tags, no FCS, plus the length; the datasheet gives no maximum) drops everything received up to `RX_WR`; above the received size waits for the rest | a corrupt length does not move `RX_RD` backwards or past `RX_WR` |
| chip select via `gpio_put` | |
| `wizchip_send_data()` removed | replaced by the new `sendFrame()` |

A reopen discards the unread receive buffer, up to its 16 KB, a ROUTING_BUSY waiting there included.

## Limits

A ROUTING_INDICATION that is on the wire before the ROUTING_BUSY reaches the chip cannot be withheld.

## Keeping it in step

When arduino-pico updates `w5500.*`, compare it against this copy and carry over fixes; the changes
above are the only intended differences.
